## 1. 产品概述

### 1.1 产品背景

地磅（汽车衡）广泛应用于矿山、电厂、钢厂、水泥厂、垃圾处理站、物流园、粮库等场景。目前多数企业仍采用人工记录称重数据的方式，存在效率低、易出错、易作弊、数据难追溯等问题。新海丽科称重软件是行业内成熟的商用地磅称重软件，本产品以其为对标，实现一套功能一致的通用型智能称重管理系统。

### 1.2 产品定位

面向地磅称重场景的 Windows 桌面端单机/网络版软件，核心解决：

- 称重数据自动采集，杜绝人工读数、抄录错误
- 两次称重（毛重/皮重）自动结算净重
- 手工录入车号，操作流程简洁，贴合现场习惯
- 摄像头实时监控、过磅自动抓拍留证，辅助防作弊
- 报表自动统计、磅单规范打印

### 1.3 目标用户与使用场景

| 用户 | 场景 |
|---|---|
| 司磅员 | 日常过磅操作、录入车号/货物信息、打印磅单 |
| 财务/统计员 | 查询称重记录、导出报表、对账结算 |
| 企业管理员 | 基础资料维护、用户权限管理、系统配置 |
| 系统管理员 | 数据备份恢复、外设调试、系统维护 |

典型场景：
1. 标准过磅：车辆上磅 → 读取稳态重量 → 手工录入车号与货物信息 → 第一次称重 → 卸/装货 → 第二次称重 → 自动计算净重 → 打印磅单
2. 人工补录：仪表故障或特殊车辆时，手工录入重量完成过磅

#### 1.4.2 架构分层（与工程骨架 src/CZRWeighSystem 一致）

```
┌─────────────────────────────────────────────┐
│ UI 层（WinForms）      MainForm 主界面        │
├─────────────────────────────────────────────┤
│ Core 层（业务）        WeighManager 称重流程  │
├─────────────────────────────────────────────┤
│ Comm 层（采集）        IWeightSource 统一接口 │
│   ├── SerialWeightSource 串口仪表（帧解析）   │
│   ├── SimulatedWeightSource 模拟器（调试用）  │
│   └── StabilityFilter 稳定判定               │
├─────────────────────────────────────────────┤
│ Database 层（存储）    SQLite 仓储 + 事务结算  │
├─────────────────────────────────────────────┤
│ Utils（横切）          日志 / 配置（JSON）     │
└─────────────────────────────────────────────┘
```

要点：
1. 数据源抽象为 `IWeightSource` 接口，串口/模拟器可配置切换，后续扩展 TCP 透传采集（F6-04）不影响业务层
2. 串口数据可能来自非 UI 线程，统一经 Invoke 转发到界面线程刷新
3. 二次磅结算采用数据库事务，保证"读取一次磅→计算净重→更新状态"原子性

#### 1.4.3 选型理由（备选方案对比结论）

| 备选 | 未采用原因 |
|---|---|
| Python | 桌面 GUI 弱、打包体积大且易被杀软误报、调用厂商 C++ SDK 困难、7×24 长期运行稳定性欠佳 |
| Qt（C++） | 开发效率低、编译环境与内存管理学习成本高，不适合首语言上手 |
| .NET Framework 4.8 | 仅在需兼容 Windows 7 老磅房电脑时另行评估（见 6.3） |

#### 1.4.4 开发与调试方式

1. 无仪表调试：内置模拟数据源（模拟"上磅→升重→稳定→离磅"全过程），开发期零硬件依赖
2. 串口联调：com0com 虚拟串口对 + 串口调试助手发送协议帧
3. 数据库调试：直接查看 exe 目录 data/weigh.db；日志按天见 logs/
4. 现场部署：Release 自包含发布，拷贝单目录即可运行，无需安装运行时

## 2. 术语定义

| 术语 | 说明 |
|---|---|
| 毛重 | 车辆满载时的总重量（车重+货重） |
| 皮重 | 车辆空载时的重量（车自重） |
| 净重 | 毛重－皮重，即货物实际重量 |
| 扣重 | 在净重基础上按比例或固定值扣除的水分/杂质等 |
| 一次磅 | 车辆第一次过磅的称重记录 |
| 二次磅 | 同一车辆第二次过磅，与一次磅配对结算 |
| 稳定重量 | 仪表数据连续 N 次采样一致时的重量值（默认 N=3~5，可配置） |
| 磅单 | 称重完成后打印的结算凭证 |

## 4. 总体业务流程

### 4.1 标准两次称重流程（核心流程）

```
车辆上磅 → 视频画面确认完全上磅 → 手工录入车号
→ 读取稳定重量 → 录入货物/单位/规格等信息 → 保存一次磅（自动抓拍留证）
→ 离场作业（装卸货）→ 再次上磅 → 匹配一次磅记录
→ 读取稳定重量 → 自动计算净重 → 抓拍留证
→ 保存二次磅（自动抓拍留证）→ 打印磅单 → 车辆离场
```

规则：
1. 同一车号存在未完成的一次磅时，二次称重自动配对；皮重模式下先皮后毛或先毛后皮均可（可配置）
2. 一次磅与二次磅必须同一车号；结算后记录锁定不可再配对
3. 长时间未完成二次磅的一次磅（默认 24 小时，可配置）在界面醒目提示
4. 支持智能判断：已知皮重的车辆可"一次磅直接结算"（快捷模式，可配置开关）

## 6. 非功能需求

### 6.1 性能

| 指标 | 要求 |
|---|---|
| 重量刷新延迟 | ≤ 200ms |
| 保存一条记录 | ≤ 1s |
| 10 万条记录查询 | ≤ 3s（常用条件建索引） |
| 稳定判定响应 | 稳定后 ≤ 0.5s 高亮 |
| 并发（网络版） | ≥ 10 个客户端同时在线 |

### 6.2 可靠性

1. 断电/崩溃保护：保存动作事务化，任何异常不产生半条记录
2. 仪表断线：界面明确告警，禁止误用旧数据保存（数据实时刷新校验）
3. 数据库断连：自动重连，期间保存操作排队并提示
4. 7×24 小时连续运行无内存泄漏

### 6.4 安全性

1. 密码加盐哈希存储（禁止明文）
2. 权限不足的操作入口隐藏或置灰
3. 数据库文件/备份文件访问控制
4. 所有敏感操作可追溯到人、到时间

1. 支持全键盘操作过磅（回车流转：车号→货物→单位→保存）

4. 深色/浅色主题，重量字体大小可调（适应磅房远距离观看）

## 10. 验收标准（MVP）

1. 模拟仪表数据下完成完整两次称重流程，净重计算正确
2. 磅单打印内容、格式与模板一致，可补打
3. 记录查询、导出、日结报表数据准确
4. 权限控制符合第 3 章矩阵
5. 断电重启后无脏数据，备份恢复可用
6. 通讯断线告警与自动重连有效
7. 连续 8 小时压力运行无崩溃、无内存泄漏

## 12. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| 各仪表协议差异大 | 采集适配工作量 | 首版实现主流 5 种协议+自定义配置框架 |
